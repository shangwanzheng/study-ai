# 阶段 0：AI 产品与能力地图——知识点与阅读材料

> 对应大纲：[`frontend-to-ai-learning-outline.md`](./frontend-to-ai-learning-outline.md)「阶段 0」  
> 建议用时：约 1 周（每天 1–2 小时阅读 + 半小时笔记）  
> 目标：能听懂 LLM / 多模态 / Agent / RAG，并判断「该不该上 AI、上哪一类能力」。

---

## 1. 你要带走的心智模型（先记这张表）

| 概念 | 一句话 | 解决什么 | 不解决什么 |
|------|--------|----------|------------|
| **LLM** | 按概率续写文本的大模型 | 理解/生成/改写/推理类任务 | 保证事实正确；替你查私有最新数据 |
| **多模态** | 能吃图/音/视频等，不只文本 | 截图理解、语音入口、文档扫图 | 自动等于「视觉搜索引擎」 |
| **Embedding** | 把文本变成可比较的向量 | 语义相似检索、聚类、去重 | 直接「回答问题」 |
| **RAG** | 先检索再让模型基于材料答 | 公司文档/知识库问答、可引用 | 代替权限系统；检索错则答案错 |
| **工具调用** | 模型选 API，你的代码去执行 | 查库、下单、调内部接口 | 自己保证工具安全与幂等 |
| **Agent** | 多步：规划→工具→观察→再决策 | 开放式多步任务、工作流 | 默认更稳；步数一多更贵更不稳 |
| **微调** | 用数据改模型行为/风格 | 稳定格式、领域口吻、特定分类 | 多数场景不如 Prompt+RAG 划算 |

**选型口诀（阶段 0 够用）**

1. 规则 / 搜索 / 表单能搞定 → **先不上模型**  
2. 只要通顺生成、无强事实 → **直接调 LLM API**  
3. 答案必须基于你们的资料 → **RAG**  
4. 需要查系统、改数据、多步 → **工具调用；复杂再 Agent**  
5. 同上仍不够且数据量/稳定性要求极高 → **再考虑微调**（阶段 5 再碰）

## 2. 知识点清单（按主题）

### 2.1 生成式 AI 产品形态

- **聊天助手**：独立对话页；状态简单，但要处理多轮上下文与「空话」。
- **Copilot（嵌入式）**：嵌在编辑器/后台/CRM 旁；关键是选区上下文、一键应用、可撤销。
- **搜索增强**：查询改写 + 检索 + 摘要；前端常要「来源卡片」。
- **工作流自动化**：表单/工单驱动；AI 填字段、分类、路由；适合结构化输出。
- **多模态**：上传图/PDF/语音；产品上要管文件大小、预览、失败重试。

**前端视角**：同一模型能力，产品差在「上下文从哪来、结果怎么落回 UI、失败怎么降级」。

### 2.2 基础术语（能讲给同事听）

- **Token**：计费与上下文的基本单位；中英文长度直觉不同。
- **上下文窗口（Context window）**：单次请求能塞进的上限；超了要截断/摘要/检索。
- **系统提示 / 用户消息 / 助手消息**：对话角色分工；系统提示像「产品规则」。
- **温度等采样参数**：更「稳」还是更「散」；业务填表通常要偏低、要校验。
- **幻觉（Hallucination）**：说得像真的但没依据；产品要用引用、拒答、人工确认压风险。
- **延迟与流式**：首 token 时间 vs 整段完成时间；流式改善体感，不降低总成本。
- **成本**：大致 ∝（输入 token + 输出 token）× 单价；重试、长上下文、Agent 多步会放大。
- **隐私与数据出境**：日志、训练集使用条款、PII；密钥与用户内容不要进前端。

### 2.3 能力边界：「能演示」≠「能上线」

上线前至少问这 6 个：

1. **对错谁负责？** 错答的业务后果是什么？要不要人工确认？  
2. **依据从哪来？** 仅靠模型记忆，还是检索/工具？无依据时是否允许编？  
3. **权限对不对？** 用户 A 会不会看到用户 B 的知识库片段？  
4. **延迟用户能否忍？** 3 秒 vs 30 秒；要不要流式、骨架屏、后台任务？  
5. **钱是否可控？** 有无按用户配额、模型路由、缓存？  
6. **被滥用怎么办？** Prompt 注入、刷接口、套娃工具调用。

### 2.4 方案选型直觉（阶段 0 核心练习）

| 需求信号 | 更可能的方案 |
|----------|----------------|
| 「帮我润色文案 / 起名 / 写邮件」 | 直接 LLM |
| 「根据我们的帮助中心回答」 | RAG + 引用 |
| 「根据订单号查状态并总结」 | 工具调用（查订单 API） |
| 「调研竞品并整理表格，中途可能改方向」 | Agent / 工作流（带步数上限） |
| 「分类标签必须极稳、海量历史样本」 | 先规则/小模型分类；微调是后手 |
| 「表单校验、权限判断、计价公式」 | **不要 AI**，用代码 |

### 2.5 五个概念的「分工一句话」（检验标准用）

- **LLM**：负责理解和生成语言。  
- **Embedding**：负责「找相似内容」。  
- **RAG**：负责「先找到材料再生成」。  
- **工具调用**：负责「让模型碰真实系统」。  
- **Agent**：负责「多步自己拆任务并循环用工具」。
